# 开发交接

## 项目目的

应用直接运行在智能眼镜，识别并绑定真实外设，在对象周围显示八方向刺激；利用原生眼动激活三个候选，再结合SSVEP与注意力或MI确认意图完成选择，保留单目标并控制移动。正常退出后恢复八方向。

当前版本是这一流程的软件原型，设备未接入。模拟注视为触控或鼠标落点，选择与确认由人工事件注入。不要把当前确认按钮当成最终产品确认方案。

## 接手优先级

1. 在自己的机器构建、运行既有测试，体验全部模拟控制流程。
2. 补上合成脑电和数据回放到SSVEP评分的真实计算链，替换人工选择结果；确认意图仍需明确标识模拟或真实。
3. 型号与SDK确定后优先验证眼镜本体部署、原生眼动权限、坐标、时间和有效状态。
4. 接实际显示与空间跟踪，处理眼动校准、有限视场、头部运动和对象失跟。
5. 有硬件后测刺激波形与个人脑电，再接真实外设并验证执行反馈。

## 必须保持的约束

- 不加入脑电判断质量门。质量诊断可记录，不能按质量分、幅值或通道数达标才放行选择、确认或执行。不自动引入新的评分阈值放行门。
- 组内精选择保持候选组，跨组切换需稳定判定，候选变化使旧结果失效。
- 眼动是眼球注视，不能把头部朝向接口静默冒充真实眼动。
- 正常退出是注意力下降且有效视线移开；眼动无效、通信中断、对象失跟等按独立故障规则处理。
- 最终移动模式及持续授权仍需细化；不要未经讨论把连续移动固定替换成离散步进。
- 不把演示投影当成真实空间锚定，也不把软件帧回调当成实际发光时间。

## 协作方式

每项任务从`main`建立独立分支，提交PR说明改动、验证结果及未验收范围。避免直接覆盖主分支。涉及设备协议、判决逻辑、确认或移动方式改变时，在PR中明确说明。

提交前运行相关单元测试、lint和构建。后续测试应验证候选版本、时序、数据来源和控制行为，不将模拟数据上的性能包装为真人结果。

本仓库仅包含开发代码与必要文档。专利原稿、原始实验数据及个人记录另行通过明确授权的渠道交接。
